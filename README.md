# Подъём · WakeUp Android

Нативный офлайновый будильник на Kotlin и Jetpack Compose. Главная функция —
проверка после отключения сигнала: если пользователь не подтвердил пробуждение,
будильник звонит снова. Никаких аккаунтов, рекламы, платных API или разрешения INTERNET.

**Версия 0.1.0 — собираемая первая версия. Физический iQOO 15R ещё не испытан.**
Она не объявляется готовой к единственному ежедневному будильнику до проверки на
устройстве. Подробности реализации и ограничения приведены ниже.

## Что реализовано

- Создание, изменение, выключение, удаление с подтверждением, дублирование,
  однократные и недельные будильники, пропуск следующего срабатывания.
- Реальный `AlarmManager.setAlarmClock`, канал CATEGORY_ALARM, Full-Screen Intent,
  foreground-служба, встроенный оригинальный звук, вибрация, плавное усиление,
  системные мелодии и собственный файл через SAF с резервным звуком.
- Snooze с интервалом и ограничением числа повторов.
- Wake Up Check с сохранением состояния, отдельными системными событиями,
  100-секундным окном по умолчанию, повторным звонком, усиленным подтверждением
  примером и 1–3 последовательными контрольными проверками.
- Уникальные экземпляры и версии событий, защита от повторного broadcast,
  звуковая очередь параллельных звонков, восстановление после загрузки/обновления,
  обработка часового пояса, DST и перевода часов.
- Математика, память, собственная фраза, акселерометр, новые шаги, точное сравнение
  QR/штрихкода. Последовательности из 1–5 заданий. CameraX + ZXing работают локально.
- Отдельное подтверждаемое аварийное завершение без блокировки телефона.
- Русский интерфейс, оригинальная иконка, тёмная/светлая тема, 12/24-часовой формат,
  диагностика разрешений, тестовый системный звонок через 10 секунд.
- Ручной дневник сна; длительность и среднее за неделю. История пробуждений,
  календарь подтверждений, серии дней, графики за 7/30 дней.
- Экспорт/импорт будильников и оформления через системный выбор документа.
  Импорт добавляет выключенные копии, не перезаписывает существующие данные.

## Сборка и установка

Нужен **полный JDK 21** (с `javac`), Android SDK platform 36 и build-tools 36.0.0.
Gradle Wrapper 8.13 включён в репозиторий, SHA-256 дистрибутива закреплён.

```bash
sdkmanager 'platforms;android-36' 'build-tools;36.0.0' 'platform-tools'
# Указать свой SDK через ANDROID_HOME или sdk.dir в local.properties.
./gradlew :core:test :app:testDebugUnitTest :app:lintDebug \
  :app:assembleDebug :app:assembleDebugAndroidTest
```

В настроенной облачной среде все эти проверки запускает `./scripts/check.sh`.
`local.properties`, SDK, JDK, кеши и ключи подписи не входят в Git.
Для Android Studio выбрать JDK 21 в Gradle JDK и дождаться синхронизации.

APK: `app/build/outputs/apk/debug/app-debug.apk`.
Тестовый APK: `app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk`.
Проверенный итоговый APK и контрольная сумма копируются в `artifacts/` рабочего
каталога; большие бинарные сборки не коммитятся.

Для установки открыть APK на телефоне и разрешить установку из выбранного источника,
либо при явно подключённом устройстве выполнить:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Debug APK подписан отладочным ключом. При смене ключа Android не позволит обновить
приложение поверх старого; для регулярных обновлений нужно сохранить собственный
ключ подписи. Ключи никогда не следует коммитить.

## Первый запуск на iQOO / OriginOS

Пройти экран «Проверка готовности будильника»: уведомления, точное расписание,
полноэкранный показ, громкость будильника, ограничения батареи. Проверить фоновые
разрешения и автозапуск в системной карточке приложения. Названия пунктов отличаются
между версиями и регионами; приложение не утверждает, что автозапуск разрешён.

Разрешение USE_EXACT_ALARM применяется на Android 13+. SCHEDULE_EXACT_ALARM ограничено
Android 12/12L через maxSdkVersion=32. До Android 12 отдельного разрешения нет.
Full-Screen Intent может быть запрещён пользователем; на разблокированном экране
система может выбрать уведомление вместо открытия Activity.

После перезагрузки до первой разблокировки работает встроенный сигнал. Личные
названия, QR, фразы и URI звуков доступны только после разблокировки. Просроченное
сохранённое событие восстанавливается немедленно — это может быть догоняющий сигнал.

**Force-stop и выключенный телефон не поддерживаются самой системой доставки.**
Поведение Doze, DND, Bluetooth, OriginOS, камеры и датчиков нужно проверить по
[ручным сценариям](docs/DEVICE_TESTS.md).

## Что ещё не реализовано

В первую версию не вошли фотосопоставление, приседания, запись и анализ звуков сна,
звуки засыпания с таймером, напоминание об отходе ко сну, голосовое объявление времени,
случайные текстовые фразы, генератор собственного QR и глобальные настройки по
умолчанию для всех новых будильников. Нет отдельного переключателя поведения кнопок
громкости: они выполняют обычное системное управление потоком будильника.

Проверки без ответа повторяются до подтверждения/аварийного завершения; отдельного
переключателя «только один повтор» нет. Несколько контрольных проверок планируются
последовательно, следующая — от момента подтверждения предыдущей.

Смена системного времени/зоны пересчитывает будущие основные события, включая ранее
пропущенное. Прошлые версии личных настроек пока сохраняются локально для истории;
для полного удаления всех данных используется системная очистка данных приложения.
Экспорт содержит личные фразы и QR; аудиофайлы не экспортируются.

Не заявляется распознавание физиологического бодрствования или фаз сна. Задания
с камерой/движениями не подменены фиктивным распознаванием. Все ограничения явные.
