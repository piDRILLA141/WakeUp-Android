# Проверки на физическом iQOO 15R / OriginOS 6

Статус всех сценариев ниже: **не выполнены на физическом телефоне**.
Сборка, Robolectric и Compose-тесты не подтверждают работу прошивки, датчиков,
камеры, аудиомаршрута и реального экрана блокировки.

## Подготовка

1. Установить debug APK. Открыть приложение хотя бы один раз.
2. Пройти «Проверку готовности». Разрешить уведомления и полноэкранный показ.
3. Проверить ненулевую системную громкость именно будильника.
4. В карточке системных настроек приложения проверить фоновую работу и автозапуск.
   Точное имя пункта OriginOS зависит от региона и версии; автоматическая проверка
   автозапуска недоступна. При необходимости выбрать режим без ограничений батареи.
5. Разрешить будильники в «Не беспокоить», если используется этот режим.
6. До повседневного использования пройти тесты A–K. Для первого утра оставить
   независимый проверенный будильник, пока поведение устройства не подтверждено.

## Сценарии и ожидаемые результаты

| Тест | Действия | Ожидаемый результат |
|---|---|---|
| A | «Будильник через 10 секунд», блокировка | Встроенный звук и вибрация, экран или доступное уведомление |
| B | Будильник через минуту, убрать приложение из недавних | Системный звонок без открытого UI |
| C | Выполнить задание, закрыть UI в ожидании проверки | Проверка появляется в назначенный момент |
| D | Не отвечать 100 секунд | Полный повторный сигнал; после задания цикл повторяется |
| E | Поставить сигнал, перезагрузить, не разблокировать | Встроенный сигнал до первой разблокировки; личные QR/фразы требуют разблокировки |
| F | Отключить интернет и мобильную сеть | Основной звонок, задания, QR и проверка работают |
| G | Дождаться сигнала в Doze и энергосбережении | Проверить доставку; отдельно записать ограничения OriginOS |
| H | Два сигнала на одну минуту, затем два wake check | Оба экземпляра в истории, одна звуковая очередь, независимые дедлайны |
| I | Запретить уведомления/full-screen, снизить громкость | Главная и диагностика показывают проблему; не обещают готовность |
| J | Зарегистрировать код, сканировать другой, затем правильный | Другой код не засчитывается; нужный код работает без сети |
| K | Экран выключен, подключён Bluetooth | Проверить слышимость, маршрутизацию и поведение DND вручную |

Дополнительные проверки:

- Поворот экрана и выгрузка UI посреди математики/памяти: выполненные задания
  сохраняются, незавершённое не засчитывается. Текущую последовательность памяти
  можно посмотреть повторно.
- «Назад» и Home не выключают звонок и не подтверждают пробуждение.
- Потерянный QR: «Не могу выполнить» → ввод «ЗАВЕРШИТЬ» прекращает текущий экземпляр,
  оставляет следующее регулярное срабатывание и запись в истории.
- Нет датчика шагов / отказ Activity Recognition: предложена математика, движение
  не имитируется кнопкой-счётчиком.
- Изменить время, включить/выключить, удалить, дублировать, пропустить следующий;
  сверить системное расписание. Копия и импорт по умолчанию выключены.
- Перевести системные часы во время snooze и Wake Up Check: интервал сохраняется
  в рамках текущей загрузки. Перевести зону: основные звонки следуют местному времени.
- Отозвать доступ к собственной мелодии: должен прозвучать встроенный «Рассвет».
- Обычный входящий звонок: экстренные и телефонные функции остаются доступны.
- Обновить приложение через `adb install -r`, убедиться в сохранении данных.
- Не использовать force-stop как тест обычной выгрузки: Android намеренно прекращает
  доставку событий остановленному приложению до его ручного запуска.

## Команды для подготовленного устройства

Команды ниже выполняет владелец после подключения собственного тестового устройства.

```bash
adb devices -l
adb install -r app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:connectedDebugAndroidTest
./scripts/device-check.sh
```

`device-check.sh` читает диагностику. Не устанавливает APK, не перезагружает телефон,
не останавливает приложение и не меняет настройки. Логи могут содержать личные
названия уведомлений; перед публикацией их следует просмотреть.

Ускоренный тест Wake Up Check есть только в debug-сборке: 10 секунд до звонка,
один пример, 10 секунд до проверки, 10 секунд на ответ. Это настоящие AlarmManager
события. Обычные пользовательские проверки используют выбранные интервалы.
