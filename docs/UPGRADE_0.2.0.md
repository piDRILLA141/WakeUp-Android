# Обновление «Подъём» до 0.2.0

## Перед установкой: подпись и сохранение данных

Не удаляйте установленную 0.1.0. Сначала откройте её Настройки → Экспорт будильников
и сохраните JSON вне каталога приложения. Проверьте наличие файла. Экспорт 0.1.0
включает будильники, фразы, QR и оформление, но не историю сна/пробуждений и не сами
аудиофайлы. Поэтому экспорт не заменяет обновление с совместимой подписью.

В новом APK сохранён applicationId `ru.podyom`, versionCode увеличен 1→2,
versionName — 0.2.0. Room runtime остаётся v2, private Room — v1; таблицы не
изменились. Старые JSON-записи читаются с безопасными значениями новых полей.
Миграция 1→2 сохранена, разрушительных миграций нет. ID прежних будильников
не изменяются. При совместимой подписи Android сохраняет данные при установке
поверх старой версии; импорт при этом не требуется.

В архиве APK сначала откройте **SIGNING.md**. Там результат сравнения сертификата
с APK из GitHub Actions запуска 42331207731 и первой опубликованной сборкой
42329696055. У разных запусков
0.1.0 могли быть разные debug-сертификаты. Сравнение с этим запуском подтверждает
совместимость только с соответствующим APK, а не со всеми когда-либо собранными.

Прежний workflow создавал случайный debug-ключ на одноразовом GitHub runner и не
сохранял его. Закрытый ключ нельзя восстановить по APK/публичному сертификату.
Если сертификаты различаются и исходный ключ отдельно не сохранён, обновление
поверх установленного APK технически невозможно. Не пытайтесь очистить данные
или удалить приложение для устранения ошибки подписи. Сохраните старую установку,
экспорт и аудиофайлы; применение APK с другим ключом — отдельное решение владельца
после сохранения данных. История 0.1.0 через её JSON-экспорт не переносится.

Для проверки с подключённого компьютера без изменения данных:

```bash
adb shell pm path ru.podyom
# Скопировать указанный base.apk через adb pull и проверить его сертификат:
apksigner verify --print-certs installed-0.1.0.apk
apksigner verify --print-certs podyom-debug.apk
# Установка поверх допускается только при совпадающих сертификатах:
adb install -r podyom-debug.apk
```

## Постоянная подпись для последующих сборок

Если исходный ключ имеется, владелец сохраняет его в GitHub → Settings → Secrets
and variables → Actions. Не публикуйте ключ/пароли в чат, Git, workflow-файл или
публичный Actions artifact. Нужны четыре repository secrets:

- `PODYOM_KEYSTORE_BASE64`: содержимое своего JKS/keystore в base64.
- `PODYOM_KEYSTORE_PASSWORD`: пароль хранилища.
- `PODYOM_KEY_ALIAS`: имя ключа.
- `PODYOM_KEY_PASSWORD`: пароль ключа.

Workflow восстанавливает ключ только во временный файл с правами 600, использует
его для debug APK и удаляет после сборки. Этот файл не попадает в Git-кеш,
исходники или артефакты. Для локальной сборки те же параметры задаются через
`PODYOM_KEYSTORE_PATH`, `PODYOM_KEYSTORE_PASSWORD`, `PODYOM_KEY_ALIAS`,
`PODYOM_KEY_PASSWORD`. Без секретов сборка остаётся стандартной debug-сборкой с
временным ключом; SIGNING.md явно отмечает это. Новый постоянный ключ помогает
будущим обновлениям, но не делает его совместимым с потерянным старым ключом.

## Что изменилось

- Сохранён `setAlarmClock`; у showIntent отдельный URI каждого экземпляра и
  официальное ACTION_SHOW_ALARMS. В Настройках есть «Системное расписание»:
  ближайший будильник, ближайшее событие, getNextAlarmClock, владелец события,
  разрешения и диагностика ошибок. Android сообщает ближайшее событие среди
  всех приложений: владелец может быть другим приложением часов. Значок выбирает
  Android/OriginOS; принудительно включить его нельзя.
- Умный ввод: 640/0640/6:40 → 06:40, 1830 → 18:30. Цифровая клавиатура,
  визуальное двоеточие, сохранение курсора; нормализация при потере фокуса и
  сохранении. Неверное 2460 остаётся ошибкой, а не произвольным временем.
- «Дублировать на 10 минут позже»: отдельный активный будильник, прежние личные
  параметры и название, сдвиг дней при переходе через полночь. Ошибки регистрации
  не выдаются за успех.
- «+ Через 20 минут»: точный момент сейчас +1200 секунд, отдельный однократный
  экземпляр, защита от повторного нажатия в течение 1,5 секунды, обычная кнопка
  выключения, без Wake Up Check и заданий. После перезагрузки событие сохраняется.
- Активная проверка использует отдельный ID уведомления и новые каналы v2.
  Уведомление ожидания сначала удаляется, поэтому OnlyAlertOnce не подавляет
  первый сигнал подтверждения и последующие циклы. Старые пользовательские каналы
  не удаляются и не перенастраиваются скрытно.
- Внутри приложения появляется крупный диалог; на экране звонка — отдельная
  панель подтверждения с таймером MM:SS, большим действием и аварийным завершением.
- «Заметность проверки пробуждения»: обычная/усиленная. Усиленная добавляет
  заметный сигнал и вибрацию. Наложение отдельно разрешается пользователем через
  официальный экран Android. Используется TYPE_APPLICATION_OVERLAY, без
  Accessibility Service и без принудительного фонового запуска Activity.
- В усиленном режиме вне приложения показывается одна ограниченная карточка с
  таймером. На заблокированном экране вместо неё запрашивается штатный Full-Screen
  Intent. При строгой проверке карточка открывает задание по явному нажатию.
  При отказе/запрете остаётся уведомление с действиями. Защищённые экраны и OriginOS
  могут запретить наложение или выбрать heads-up вместо полноэкранного показа.

## Проверки владельца на iQOO 15R

0.1.0 владелец уже проверял лично; ниже новые сценарии 0.2.0, пока не испытанные
разработчиком на физическом телефоне:

A. Ввести 640, сохранить 06:40; проверить удаление, перемещение курсора и вставку.
B. Скопировать 06:30; проверить отдельный активный 06:40 и неизменность оригинала.
C. Скопировать 23:55; проверить 00:05 и сдвиг пятницы на субботу.
D. «Через 20 минут»; два быстрых нажатия должны дать один будильник, после
   выключения он не должен повториться завтра. Проверить восстановление после boot.
E. Выполнить задание, заблокировать экран и дождаться проверки; проверить новое
   разрешение/канал, звук, вибрацию и доступ к подтверждению.
F. Использовать другое приложение при обычной проверке; затем усиленную с
   добровольно разрешённым наложением. Отдельно проверить отзыв разрешения и
   защищённые экраны. Карточка не должна перехватывать касания вне своей области.
G. Подтвердить вовремя, в том числе двойным нажатием; повторного звонка нет.
H. Не подтвердить, проверить повторный звонок и новую заметную проверку в следующем
   цикле. Просроченное подтверждение не должно засчитываться.
I. Подтвердить/аварийно завершить/дождаться таймаута: нет оставшихся окон и
   уведомлений. Проверить несколько параллельных проверок.
J. Сравнить сертификаты, выполнить совместимое обновление без очистки данных,
   проверить прежние будильники, QR, настройки и историю.

В диагностике сверить getNextAlarmClock после изменения, удаления, перезагрузки
и при нескольких будильниках. Поведение самой иконки, Full-Screen Intent, звука,
Doze, DND, Bluetooth, защищённых окон и энергосбережения OriginOS нельзя доказать
unit-тестами или Robolectric. Фактические автоматические результаты — в артефакте
`podyom-check-results`, включая SIGNING.md и сертификаты.
