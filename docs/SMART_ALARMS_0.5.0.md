# Подъём 0.5.0 · этап B

Новый основной звонок заменяет незавершённое задание связанного будильника в
пределах 90 минут одного местного календарного дня. При одинаковом времени
порядок определяется идентификатором экземпляра. Старый экземпляр остаётся
в истории как пропущенный. Доставка его системного события уже не возобновит
звонок. У быстрых и независимых будильников отдельные сеансы. Отложенные
вручную сигналы сохраняются. Для обычных будильников настройка «Не
накапливать пропущенные будильники» включена по умолчанию. У уже начатых
негруппированных последовательностей Wake Up Check сохраняется свой ход.

Внутри группы следующий основной звонок может заменить и начатую проверку.
Сама принадлежность к группе сохраняется при перезапуске. Общий выключатель
группы приостанавливает будущее расписание и сохраняет выбор отдельных
переключателей. Звонки, которые уже начались, остаются доступны. При удалении
группы выберите, сохранять ли её будильники. По умолчанию сохранять.

Умная отмена выключена для новых групп. После последней успешной проверки
или завершения всех заданий будильника без Wake Up Check пропускаются ещё
будущие связанные сигналы в пределах 90 минут от исходного срабатывания в
тот же местный календарный день. Например, 23:55 не отменит 00:05. Сигналы
других групп, независимые будильники и повторы следующих дат сохраняются.
Восстановить отменённый сигнал можно в меню его карточки до времени звонка.

## Проверка на iQOO 15R

1. Поставьте три обычных будильника на ближайшие минуты. Удерживайте карточку,
   выберите все три и нажмите «Объединить в группу». Укажите название.
2. Пропустите первый и второй. На третьем выполните его задание. В истории
   первые два должны отображаться пропущенными. Подтвердите Wake Up Check.
   Проверьте, что старые задания, уведомления и карточки не возвращаются.
3. Добавьте более поздний сигнал, включите умную отмену и повторите. При двух
   проверках дождитесь второй. Убедитесь, что только после неё резерв отменён
   и завтра сохранён. Восстановите резерв до его времени.
4. Повторите с выключенной умной отменой и с истёкшей проверкой. Будущий
   резерв должен остаться. Проверьте независимый таймер «Через 20 минут».
5. Выключите группу, предварительно выключив один её будильник. При включении
   этот будильник должен остаться выключенным. Пропустите группу на завтра,
   перезагрузите телефон, проверьте пропуск и отмените его.
6. Повторите открытие Wake Up Check из TikTok и при блокировке экрана. В случае
   сбоя сохраните время и JSON через «Настройки → Экспорт диагностики».

## Установка и подпись

Сравните SHA-256 сертификатов в SIGNING.md. При несовпадении Android отклонит
обновление. Сохраните установленную версию и экспортируйте будильники. В
резервную копию входят группы, состав и их настройки. История, дневник сна
и файлы мелодий через этот экспорт не переносятся. Для установки поверх
нужен исходный ключ. Миграция Room 2 → 3 сохраняет таблицы будильников, истории
и событий. Дневник и личные профили остались в отдельной базе.

Владелец хранит постоянный ключ и его резервную копию в защищённом месте.
В GitHub Settings → Secrets and variables → Actions задайте
`PODYOM_KEYSTORE_BASE64` (весь keystore в base64), `PODYOM_KEYSTORE_PASSWORD`,
`PODYOM_KEY_ALIAS`, `PODYOM_KEY_PASSWORD`. Если исходный закрытый ключ доступен,
используйте его. Иначе выберите постоянный ключ для будущих установок. Не
передавайте значения в чате или Git. Для локальной сборки вместо base64
доступна переменная `PODYOM_KEYSTORE_PATH` с остальными параметрами.

Для сборки, которая обязана использовать постоянную подпись, запустите
workflow вручную и включите `require_persistent_signing`. Без настроенного ключа
обычный CI продолжит проверки с временной тестовой подписью. Такой APK предназначен
для чистой тестовой установки. Закрытый ключ нельзя получить из сертификата APK.
